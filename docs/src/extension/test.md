# Testing Extensions with PGRX

Both `cargo test` and `cargo pgrx test` can be used to run tests using the `pgrx-tests` framework.
Tests annotated with `#[pg_test]` will be run inside a Postgres database.

## Sharing the test schema

An extension and its dependencies can all use `#[pg_schema] mod tests`. The test harness creates
the `tests` schema before `CREATE EXTENSION ... CASCADE`, and test-mode SQL generation omits
the schema's creation. Each extension owns its objects inside `tests`; the schema itself is not
a member of any extension. Other schemas and normal SQL generation retain their usual behavior.

This does not isolate object names. Same-named objects in `tests` normally fail to create. SQL
that permits replacement can instead replace an existing object, subject to PostgreSQL's
ownership checks. For functions, the argument signature also matters. Choose distinct names
across extensions for objects that must coexist.

Rebuild and reinstall dependency test artifacts generated by older cargo-pgrx versions. When
loading artifacts generated with `--test` manually, create `tests` before loading the extensions;
the harness normally handles this step.

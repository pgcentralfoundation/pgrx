# The pgrust target for pgrx extensions

Status: experiment (2026-09-20), draft PR against pgrx. Ten pgrx
extensions install and run inside pgrust from unchanged source: the
pgrx-examples `strings`, `arrays`, `srf`, `json`, `spi`, `aggregate`,
`composite_type`, plus `pg_jsonschema`, `pg_graphql`, and a GUC/`_PG_init`
test extension. Proof: `pgrust-e2e/run.sh` (§7).

## 1. The model

pgrx extensions cannot load into pgrust as they are: pgrx's `pg_sys` is a
bindgen dump of the C headers, every backend call goes through a `sigsetjmp`
barrier, `CurrentMemoryContext` is a process global, and the `.so` is found by
`dlopen`/`dlsym`. pgrust has no C ABI, returns
`PgResult` instead of longjmp, threads `Mcx<'_>` explicitly, and registers
extension code as in-tree crates.

So the fork adds a `pgrust` *target feature* to pgrx beside `pg13`..`pg19`.
Everything above the boundary (`#[pg_extern]`, `Spi`, `JsonB`, `Array`,
`PgHeapTuple`, aggregates, GUCs, the SQL entity graph) is unchanged; the
boundary is replaced:

| pgrx piece | on Postgres | under pgrust |
|---|---|---|
| `pgrx-pg-sys` bindings | bindgen of the C headers | `pgrx-pg-sys/src/pgrust/`: C-layout types harvested from the PG18 bindings (`types.rs`, generated by `scripts/pgrx-harvest-bindings.py`), hand-written shims for every function pgrx calls |
| function wrapper | `extern "C-unwind" fn f_wrapper(fcinfo) -> Datum`, found by `dlsym` | `fn f_wrapper(Option<&mut FmgrInfo>, &mut Fcinfo) -> PgResult<Datum>` (pgrust's `PGFunction`), registered in a `linkme` slice; `dfmgr` resolves `AS 'MODULE_PATHNAME', 'f_wrapper'` through the registry |
| errors | longjmp caught by `sigsetjmp`, re-raised with `pg_re_throw` | a shim that gets `Err(PgError)` panics with a `PgrustError` payload; the wrapper's single `catch_unwind` (`call_v1`) turns any payload back into `Err(PgError)`; NOTICE/WARNING go through `elog::ThrowErrorData` |
| memory | `CurrentMemoryContext` global, `palloc`/`pfree` | a per-thread current-context cell armed by `call_v1` with the call's result context; `palloc` prefixes a chunk header so `pfree`/`repalloc`/`GetMemoryChunkContext` work; `pfree` of memory pgrust allocated is a no-op |
| SQL script / control file | `cargo pgrx schema` reads the `.pgrxsc` section of the `.so` | the same serialized entities join a `linkme` slice; `register_extension` generates the SQL with `PgrxSql::build().to_sql()` at server start and registers it as an *embedded extension* (`dfmgr::register_embedded_extension`), which `CREATE EXTENSION` reads instead of files |
| `_PG_init` | `dlsym` after load | `#[pg_guard] fn _PG_init` joins a `linkme` slice; the library's `pg_init` hook runs it on first load in a session |
| SRFs | value-per-call over `fn_extra`/`FuncCallContext` | `SetOfIterator`/`TableIterator` materialize through `funcapi::InitMaterializedSRF` |
| `Spi` | C `SPITupleTable`/`_SPI_plan`/`PortalData` pointers | `pgrx/src/spi_pgrust/` over pgrust's `spi` crate (handles, `tuptable_with`) |
| heap tuples / tupdescs | C structs read in place | C-layout images built from pgrust's `TupleDescData`/`HeapTupleData` on every call (`pgrust/tuples.rs`) |
| custom GUCs | `DefineCustomXVariable` writes `valueAddr` | new `guc::DefineCustom{Bool,Int,Real}Variable` in pgrust; `GucSetting::get()` reads the store by the setting's address |
| thread check | panics off the main thread | removed; a backend is one thread |

## 2. Layout

* `crates/pgrx/{pgrx,pgrx-macros,pgrx-pg-sys,pgrx-sql-entity-graph}` — the
  vendored fork (pgrx 0.19.2 @ 70383e88, bindings stripped; `UPSTREAM.md`,
  `scripts/vendor-pgrx.sh`). Upstream code is touched only with
  `#[cfg(feature = "pgrust")]` arms so rebasing stays cheap. The same
  code is on the fork branch `malisper/pgrx:pgrust-target` (draft PR
  upstream) as a straight copy, including the host path deps.
* `crates/pgrx/pgrx-pg-sys/src/pgrust/` — the target: `mem`, `error`, `fmgr`
  (the C-shaped call frame), `bridge` (SQL-callable builtins with the C
  `fn(FunctionCallInfo) -> Datum` shape), `funcs`, `tuples`, `guc`, `srf`,
  `registry`, `types` (generated), `oids_table` (the PG18 OID enum).
* `crates/ext/<name>` — extension crates, one per extension, `crate-type =
  ["rlib"]`, `pgrx = { path = "../../pgrx/pgrx", default-features = false,
  features = ["pgrust"] }`, `<name>.control` in the crate root.
* the host's startup links the extension crates and calls each
  `init_seams()`.
* pgrust-side changes: `dfmgr` (embedded extension registry), the
  `extension` commands (control/script/version reads route through it),
  `guc` (`DefineCustom{Bool,Int,Real}Variable`, `finish_custom_definition`),
  `guc_tables::vars` (placeholder slots).

## 3. Adding an extension

1. Copy the crate under `crates/ext/<name>`; replace its manifest with the
   rlib/pgrust shape above and pin its deps to versions already in
   `Cargo.lock` where possible.
2. Link it into the host and call `<name>::init_seams()` at host startup.
3. Add its statements to `crates/ext/_e2e/pgrx-examples.sql`.
4. `cargo check -p <name>`; a missing `pg_sys` item names the next shim.

Triage before copying: grep the crate's `pg_sys::` uses. Type OIDs, `Datum`,
`FunctionCallInfo`, memory calls, `Spi`, `JsonB`, heap tuples, GUCs: expect
zero changes. Syscache/catalog reads, hooks, `static mut` state: small
changes. `PlannerInfo`, `Buffer`, `Page`, `IndexAmRoutine`, `FdwRoutine`:
out of reach (§6).

Version cfgs inside the extension (`#[cfg(feature = "pg18")]`) need a
`pgrust` arm; the `spi` example needed one line.

## 4. What the shims cost

* Every `palloc` carries a 48-byte header and a hash-set insert; `pfree`
  a lookup. Extension code only.
* Detoast results, builtin outputs, quoting results are copied once into a
  `palloc` chunk so pgrx may `pfree` them.
* Heap-tuple and tupdesc shims rebuild a pgrust descriptor from the C image
  on each call (natts attribute copies).
* SRFs materialize the whole result; value-per-call is not offered.
* `fn_mcxt` is a dedicated context per resolved `FmgrInfo`, dropped with it.

## 5. Not done

* Enum GUCs, GUC check/assign/show hooks.
* `numeric_normalize`, range types (`lookup_type_cache`/`make_range`),
  timezone-name helpers: shims raise "not supported under pgrust yet".
* Background workers, shared memory, LWLocks, hooks (`ProcessUtility` and
  friends), triggers, relations, catalog/syscache access, `PgList`/nodes,
  `fn_call`: modules gated out of the pgrust build (`pgrx/src/lib.rs`).
* `cargo pgrx test`: extensions' `#[pg_test]` suites do not run yet; the
  proof is `crates/ext/_e2e`.
* Dynamic loading of Rust plugins: extensions are compiled in.

## 6. Out of reach

Extensions that walk planner/executor nodes or drive buffers, pages, index
AMs or FDWs (`wrappers`, `pgvectorscale`, `paradedb`). pgrust's nodes are
typed Rust structs with lifetimes, not tagged C pointers, and its AM/FDW
dispatch is a closed enum. The storage layer could be shimmed and the AM/FDW
dispatch could become a trait registry; plan-walking code would be a rewrite.

## 7. Running the proof

```
cargo build -p main_main --features pgrx-ext
crates/ext/_e2e/run.sh            # initdb (Homebrew PG18), boot, replay the suite
```
Expected: every statement returns its Postgres result; the only `ERROR`
lines are the deliberate ones (out-of-range SET, `SET x.verbose` which C also
rejects).

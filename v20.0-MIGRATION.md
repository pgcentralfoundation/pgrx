# v20.0 Migration Guide

This release fixes pgrx APIs that let safe code cause undefined behavior, and
APIs that failed on valid input. The sections below describe the fixes that
change a signature or behavior. For the move from pgrx's handwritten C macro
ports to the generated macros, see
[Using PostgreSQL C Macros](docs/src/extension/c-macros.md#migrate-handwritten-helper-calls).

## Heap tuple helpers

`pgrx::htup::composite_row_type_make_tuple` is now an `unsafe fn`: the caller
must pass a live composite Datum. It also fully detoasts the row, so a stored
composite with a one-byte header is read correctly.
